# 开发与验证记录

用户确认四视图设计和 Native 执行计划后，按 Superpowers TDD 流程完成六个任务。每个组件先出现可解释的失败测试，再实现并通过；最后进行独立整体审查及真实设备验收。

## 结果

- CPU/Qt 全套：27 passed，1 项真实 GPU 用例需显式开启。
- 真实 GPU：3 passed，检查换深度、换 RGB、换内参、Z 一致和 CPU 输出所有权。
- D435i 实机最终验收：60.000 秒，600 帧，9.983Hz；几何检查通过，逐帧分项失败计数为零。
- GUI OpenGL 四视图截图已在本机检查；图片含私人相机画面，不提交仓库。
- 相机 SDK 停止后重新开流验证通过；GUI 退出后线程清理通过。未进行物理 USB 拔插测试。
- 独立审查发现的验收清理错误、静止输出误判、停滞时旧 Hz 和无限验证时长问题均已通过回归测试修复。

## 诊断与范围

Qt6 初次真实显示缺少 `libxcb-cursor.so.0`，ldd 确认后安装 Ubuntu `libxcb-cursor0`，OpenGL 正常。

相机曾出现 RGB 正常、深度流不出帧。SDK DEBUG 日志确认失败发生在 stereo 流，不是 TRT 或 GUI。检查设备未被其他进程占用、sync mode=0、HDR=0；一次诊断性设备复位恢复，两次后续停止/开流正常。应用保留明确的超时错误和人工重新连接恢复方式，没有自动复位固件。

首轮 60 秒报告曾出现几何标记失败，当时未保存分项像素信息；随后独立 60 帧诊断未复现。为避免未知标记与截止之后的数据干扰验收，加入逐帧非有限/非正深度和 Z 不一致计数，并将几何与刷新统计均限制在稳定期。最终 60 秒复测所有分项为零。首轮异常的具体像素原因未证实，不能据此宣称修复了模型精度问题。

## 实施决定

- 保留原工作区既有优化修改，在独立克隆的目标仓库发布；不搬动或提交权重、引擎和私人截图。
- 验收和显存采样放入 `verification.py`，与 CLI 分离，便于直接测试接受条件；增加了一个内部模块。
- Hz 使用最近 2 秒滑动统计，以便没有新结果时降为零；短时间读数会比长期均值更有波动。
- 验证时长必须有限且为正，正常 GUI 不设置该参数时持续运行。

发布到指定仓库、提交代码和文档由用户后续明确授权。原 LingBot-Depth 工作区不创建提交；目标仓库沿用已有 main 分支与 Apache-2.0 许可。
